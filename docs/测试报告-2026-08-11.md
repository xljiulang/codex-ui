## 四、本次回归发现并修复的测试脚本问题（非应用缺陷）

1. **`verify-diff.mjs` / `verify-mentions.mjs` 场景 6 找不到变更行**：ToolCard 已默认折叠，变更行在折叠时不在 DOM；脚本直接查询 `.change-row` 导致误报“未出现变更行”。修复：先点击“文件变更”卡片头展开再查询/点击（直连 CLI 与 UI 均确认 apply_patch 正常执行、diff 预览功能完好）。
2. **`verify-diff.mjs` / `check-mode-lock.mjs` / `verify-approval.mjs` 选择器过时**：仍用 `textarea` / `[title="新建对话"]`，与 TipTap 编辑器（`.ProseMirror` + `window.__CODEX_UI_EDITOR__`）和 `aria-label` 导航不匹配。已全部适配。
3. **`verify-mentions.mjs` 混编断言误报**：附件 chip 文本带尾随空格，脚本用精确 `includes` 比较导致 FAIL（实际布局正确）。改为归一化 `startsWith` 比较。
4. **`verify-mentions.mjs` 环境依赖检查**：`$ida-pro-mcp:idapython` 与 `@IDA Pro MCP` 两项依赖已卸载的 mrexodia 插件；环境缺失时显式 SKIP（原逻辑硬性超时）。场景 6 另增加一次 apply_patch 重试（模型偶发不执行工具）。

## 八、输入框粘贴图片/文件（新增功能，2026-08-11 追加）

### 行为

- 图片：截图/网页位图落盘到 `%TEMP%\codex-ui-paste\`（写入失败回退应用数据目录）后以 `localImage` 进附件区；资源管理器复制的图片文件优先用剪贴板原始路径（`CF_HDROP`），不落盘。
- 非图片文件：仅支持原始路径（复制文件后 Ctrl+V），读不到原始路径时提示「暂不支持该粘贴（无法获取原始路径）」。
- 纯文本粘贴不受影响；单张图片 >20MB 提示跳过；一次可粘贴多个文件/图片。

### 实现

- Rust：`save_pasted_image`（字节落盘，扩展名白名单，临时目录优先/应用目录兜底）、`clipboard_file_paths`（`clipboard-win` 读 `CF_HDROP`）；+3 单测（共 18）。
- 前端：`ComposerBar.vue` `editorProps.handlePaste`——在 paste 事件同步阶段先取出 `File`（`DataTransferItem` 事件结束后失效），再异步解析路径/落盘。
- 单测：`ComposerBar.spec.ts` +7（位图落盘/图片原路径/文件原路径/不可解析提示/超大跳过/纯文本/混合）。

### 验证

- `npm test` 213/213；`cargo test` 18+3；`verify-core.mjs` 12/12（新增粘贴场景）。
- **真实剪贴板 E2E**：PowerShell `SetFileDropList` 放入 .txt → 应用内真实 Ctrl+V → `clipboard_file_paths` 命中原始路径、附件区出现 `@xxx.txt`；`Clipboard.SetImage` 放入位图 → 真实 Ctrl+V → 图片落盘 `%TEMP%\codex-ui-paste\`、缩略图渲染、文件存在。测试后已恢复剪贴板。
- **真实环境发现并修复 1 个缺陷**：最初把 `getAsFile()` 放在异步处理中调用，真实 WebView2 中 paste 事件结束后 `DataTransferItem` 失效导致附件不出现（合成事件用普通对象未暴露）；改为同步取出 File 后通过。
- 测试产生的临时粘贴图片已清理。
