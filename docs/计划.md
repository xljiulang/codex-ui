# codex-ui 实施计划与实现说明

## 摘要

构建 Windows 可执行程序 `codex-ui.exe`：基于 Tauri 2（Rust 后端 + Vue 3 + Vite + TypeScript 前端）的独立窗口应用，UI 复刻 VS Code Codex 插件（历史列表、聊天流、工具卡片、权限/任务模式、审批弹窗）。后端通过 `codex app-server --stdio`（官方桌面/VS Code 插件同款 JSON-RPC 协议，验证基线 codex-cli 0.146.0-alpha.9.2）与 codex CLI 通信；**codex-ui.exe 启动时所在目录即 codex 工作目录**，复用现有 `~/.codex` 会话存储。

执行过程全程可视化：命令/工具调用显示真实命令、实时输出与实时耗时；所有人工交互（提权审批、提问、MCP 表单）都有 UI 弹窗，并播放提示音、必要时把窗口置前。

## 架构

```
codex-ui.exe（Tauri 2 窗口）
├── Rust 后端（src-tauri/src/codex/）
│   ├── app_server.rs  拉起 codex.exe app-server --stdio（换行分隔 JSON-RPC），
│   │                  断线自动重连；把通知流式转发前端、响应按 id 回填
│   ├── commands.rs    Tauri 命令：会话/对话/审批/目标/设置/服务状态等
│   └── settings.rs    本地设置读写（%APPDATA%\com.codexui.app\settings.json）
└── Vue 3 前端（src/）
    ├── composables/useCodex.ts  状态中心 + 事件订阅 + 协议调用
    └── components/              头部、历史、聊天流、工具卡片、输入区、弹窗、设置
```

- 工作目录：进程启动时的当前目录（`std::env::current_dir()`），即“codex 的工作目录”。
- 会话存储：复用 codex 全局会话库（`%USERPROFILE%\.codex\sessions`），按用户隔离、跨盘共享；每个会话记录自己的 `cwd`。

## 功能实现

### 聊天与历史
- 历史列表：显示**全部目录**的会话（不做 cwd 过滤），每条显示会话标题与所属工作目录，支持“加载更多”分页、重命名、固定置顶（带“置顶”徽章）、搜索（带摘要）、删除确认。
- 打开历史会话为**只读加载**（`thread/read`），不会触发服务端自动执行；用户真正发消息时才 `thread/resume` 再 `turn/start`。
- 继续执行使用**会话记录的 cwd**（实测 `thread/resume` 返回该值），命令在该目录运行；沙箱可写根（`sandboxPolicy.writableRoots`）同样跟随会话 cwd，避免越权或误弹审批。
- 带**活跃目标**的会话在恢复后会自动持续执行目标（codex 目标模式语义）；因此“打开即恢复”会引发连续回合，故改为发消息时才恢复。
- 窗口标题：有会话时显示会话标题（无前缀）；前端头部只显示当前工作目录（点击可在资源管理器中打开）。

### 消息与内容渲染
- 用户消息：文本 + 附件；本地图片附件渲染为真实 `<img>`（Tauri asset 协议，`convertFileSrc`），不再显示路径文本；`@文件`/技能显示为标签。
- 时间与分组：助手最终答复按 `startedAtMs` 显示 HH:mm 时间戳（用户消息不显示），跨天自动插入日期分隔线。
- 交互：图片点击灯箱预览、加载失败占位；用户消息气泡保持简洁（不显示复制/重试/时间），助手最终答复可复制；未知消息类型显示友好提示并可展开原始数据。
- 引用发送格式与 VS Code 扩展对齐（经中间层代理抓包验证）：`@` 文件序列化为 `# Files mentioned by the user:` 文本段（单条 text）；`$` 技能序列化为 `[$name](path)` 文本链接并保留结构化 `UserInput::Skill` 项（fork 会注入 SKILL.md 内容）；图片为 `localImage` 结构化项。详见 [引用与附件](引用与附件.md)。
- 助手消息：`item/agentMessage/delta` 流式渲染 Markdown（表格、代码块带“复制”按钮与语言徽标、highlight.js 语法高亮）；链接按类型打开——http/https 走默认浏览器，本地文件/目录（`file:///`、`/D:/`、`D:/`、`D:\` 及 marked 编码形式、相对路径按工作目录解析）经 `reveal_path` 用资源管理器定位/打开；流式期间展示文本节流（≤80ms 刷新一次），结束时立即刷净。
- 思考过程：流式期间默认展开并实时计时，完成后自动折叠，显示耗时；内容完整展示，不限高。
- 工具卡片：
  - 命令执行卡：头部显示真实命令（优先 `commandActions[0].command`）、工作目录、状态、**实时耗时**（进行中只显示一次“进行中”+ 秒表）、实时输出（可展开/收起，渲染截断为末尾 5000 行并提示）、命令一键复制、失败显示退出码。
  - 工具调用卡（MCP/动态工具）：server/tool、参数 JSON、结果、错误。
  - 文件变更卡：add/delete/update 列表 + 差异（diff）渲染；点击文件路径/名称在**独立 Tauri 窗口**中打开预览（原生可调整大小，工具栏含全屏/关闭），单栏内联完整文本 diff（旧行红在上、新行绿在下、中间“旧 | 新”分隔、双行号列，覆盖文件全部内容），右侧滚动条式变更位置指示条（删除红段/新增绿段）。
  - diff 解析在 Rust 完成（`codex::diff`）：`build_diff_preview` 一次 IPC 完成路径解析 + 读文件 + unified diff 反向重建旧内容 + 内联行生成；二进制/读取失败/格式异常回退完整统一 diff。窗口参数经 Rust 共享状态传递，窗口按 label=`diff-preview` 识别（不依赖 localStorage）。
  - 其他：webSearch（查询词）、计划/待办列表。

### 输入区
- 通栏输入框为 **TipTap（ProseMirror）富文本编辑器**（占满底栏），文本与引用（插件/非图像文件/技能）内联混编：插件与非图像文件显示 `@` 前缀、技能显示 `$` 前缀，图片仍显示在输入框下方缩略图附件区；权限模式、任务模式、模型、发送按钮**悬浮在输入框之上、靠底对齐**（纯 CSS，注意 DOM 绘制顺序与 z-index 层级）。
- `@` 触发菜单：文件搜索（模糊结果 + 「选择文件…/选择文件夹…」固定行在前）与插件联合搜索（VS Code 风格，输入 token 时命中插件排在命中文件前）；插件列表为**对话级缓存**——进入对话（应用启动初始新对话、新建对话、打开历史会话）时预初始化 `plugin/list`，同对话复用、切换对话取各自缓存，不回退 `skills/list`；插件行显示接口返回的图标（`composerIconUrl`/`composerIcon`，缺失时品牌色首字母占位）。`$` 技能选择保留原行为（打开菜单时加载 `skills/list`）；`+` 添加内容按钮已移除。
- 发送序列化：**全部内联链接**（对齐 VS Code）——文本与引用按输入顺序交织：文件 `[名称](相对路径)`、插件 `[@名称](plugin://pluginId)`、技能 `[$名称](路径)`，不再生成 Files 段与 `## My request:` 标记；结构化 `UserInput::Skill` 项保留（SKILL.md 注入不变）；回显按内联链接顺序渲染插件/文件 `@名称`、技能 `$名称`，顺序与输入一致。
- 权限模式：请求批准 / 帮我批准 / 完全访问权限；任务模式：执行 / 计划 / 目标（目标模式弹目标对话框）。
- **上下键选择输入历史**（仅内存，行为类似 Linux shell：↑ 回退、↓ 前进、到末尾清空；多行时光标在第一行才触发）。
- 对话进行中权限/任务模式按钮**禁用**（不弹提示），回合结束后恢复。
- 模型：下拉选择（`model/list`），推理强度跟随模型动态生成；模型按钮显示“名称(强度)”；输入区左侧上下文窗口百分比椭圆框，悬停显示“上下文已用 xx K，共 yy K”。
- 发送/停止二合一按钮；新建对话前可选项目目录（默认启动工作目录）。

### 权限与交互
- 权限模式映射（`src/lib/permissions.ts`）：
  - 请求批准 → `approvalPolicy: "on-request"` + `sandboxPolicy: workspaceWrite` + `approvalsReviewer: "user"`；
  - 帮我批准 → `"on-request"` + `workspaceWrite` + `approvalsReviewer: "auto_review"`；
  - 完全访问 → `"never"` + `dangerFullAccess`。
- 审批弹窗按 `availableDecisions` 渲染：批准 / 拒绝 / 本次会话批准 / 批准并记住此规则（`acceptWithExecpolicyAmendment`）。
- 提问弹窗（选项/自由输入/密码）、MCP 表单弹窗；弹窗出现时播放提示音（`src/assets/notify.wav`）并将窗口置前（可设置关闭）。

### 设置与状态
- 设置页：codex 可执行文件路径（留空用 PATH）、Enter 快捷发送开关、跟进处理方式（调整方向/加入队列）、提示音开关（权限模式、模型、推理强度为进程级，由输入区按钮菜单配置，重启恢复默认）。
- 本地设置文件：`%APPDATA%\com.codexui.app\settings.json`。
- 登录入口已移除（假设用户通过其它入口完成 codex 登录；API Key 模式可用）。

## 关键设计决策与踩坑记录

- **历史 cwd 过滤**：`thread/list` 的 `cwd` 过滤是精确匹配；曾因初始化时序（`refreshServer` 与 `refreshThreads` 并行）导致过滤失效而显示全部会话，已改为先取工作目录再加载；最终按需求改为展示全部会话并标注目录。
- **窗口标题权限**：动态改标题需在 capabilities 中启用 `core:window:allow-set-title`。
- **图片渲染**：启用 asset 协议需在 `tauri.conf.json` 配置 `assetProtocol` 并在 Cargo 依赖开启 `protocol-asset` 特性。
- **沙箱映射**：请求批准必须用 `workspace-write` 沙箱，否则“批准并记住此规则”后写入仍被拒（曾误映射为 read-only）。
- **目标自动续跑**：带活跃目标的会话被 `thread/resume` 恢复后会连续自动跑回合，UI 表现为发送/停止按钮交替；解决方式是打开会话只读、发消息时才恢复。

## 测试

- 前端单元测试（vitest，`npm test`）：格式、权限映射、ToolCard 耗时与命令显示、MessageItem 图片渲染等。
- Rust 集成测试（`cargo test`）：真实 `codex app-server --stdio` 全流程（initialize → thread/list → thread/start → turn/start → turn/completed → delete）。
- 端到端探针（`scripts/`）：`verify-approval.mjs`（记住规则审批）、`check-mode-lock.mjs`（回合中模式按钮禁用）、`probe-approval*.mjs`（协议决策验证）。
