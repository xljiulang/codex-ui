# codex-ui 实施计划与实现说明

## 摘要

构建 Windows 可执行程序 `codex-ui.exe`：基于 Tauri 2（Rust 后端 + Vue 3 + Vite + TypeScript 前端）的独立窗口应用，UI 复刻 VS Code Codex 插件（历史列表、聊天流、工具卡片、权限/任务模式、审批弹窗）。后端通过 `codex app-server --stdio`（官方桌面/VS Code 插件同款 JSON-RPC 协议，验证基线 codex-cli 0.146.0-alpha.9.2）与 codex CLI 通信；**codex-ui.exe 启动时所在目录即 codex 工作目录**，复用现有 `~/.codex` 会话存储。

执行过程全程可视化：命令/工具调用显示真实命令、实时输出与实时耗时；所有人工交互（提权审批、提问、MCP 表单）都有 UI 弹窗，并播放提示音、必要时把窗口置前。右侧常驻面板为底部三 Tab：**历史会话**（全量会话管理）、**会话资源**（当前会话工作目录的文件树管理，含名称搜索、右键管理、文件变化自动刷新）与**Git 更改**（当前会话工作目录所在仓库的已更改文件列表 + diff 预览，未入库目录可一键 `git init`）。

## 架构

```
codex-ui.exe（Tauri 2 窗口）
├── Rust 后端（src-tauri/src/codex/）
│   ├── app_server.rs  拉起 codex.exe app-server --stdio（换行分隔 JSON-RPC），
│   │                  断线自动重连；把通知流式转发前端、响应按 id 回填
│   ├── commands.rs    Tauri 命令：会话/对话/审批/目标/设置/服务状态等
│   ├── session_fs.rs  会话资源文件系统命令：列表/搜索/元信息/重命名/删除/复制粘贴 +
│   │                  基于 notify 的递归监听（300ms 防抖，emit session-fs/changed）；
│   │                  session_fs_icons 系统文件类型图标（SHGetFileInfo → PNG data URI）；
│   │                  session_fs_read_bytes 二进制预览读取（base64，PDF 预览用）
│   ├── terminal.rs   终端会话：portable-pty（Windows ConPTY）启动 PowerShell，输出事件流、
│   │                  输入/缩放/kill 命令，会话表支持多开
│   ├── git.rs         Git 更改：内置 gix 实现状态/diff/初始化（零系统 git 依赖），
│   │                  仓库递归监听（300ms 防抖，emit git-changes/changed）
│   └── settings.rs    本地设置读写（%APPDATA%\com.codexui.app\settings.json）
└── Vue 3 前端（src/）
    ├── composables/useCodex.ts  状态中心 + 事件订阅 + 协议调用
    ├── composables/useSessionFs.ts  会话资源状态：根目录解析、懒加载缓存、展开/搜索/操作、
    │                                文件监听事件刷新
    ├── composables/useGitChanges.ts  Git 更改状态：仓库检测、刷新、一键初始化、监听事件刷新
    └── components/              头部、右侧面板（RightPanel + HistoryView + ResourceView）、
                                聊天流、工具卡片、输入区、弹窗、设置、
                                特殊文件预览（PreviewPane / PdfPreviewPane）、终端（TerminalPane）
```

- 工作目录：进程启动时的当前目录（`std::env::current_dir()`），即“codex 的工作目录”。
- 会话存储：复用 codex 全局会话库（`%USERPROFILE%\.codex\sessions`），按用户隔离、跨盘共享；每个会话记录自己的 `cwd`。

## 功能实现

### 聊天与历史
- 历史列表：显示**全部目录**的会话（不做 cwd 过滤），每条显示会话标题与所属工作目录；目录按名称 A-Z、会话按置顶+时间倒序排序；全量加载、重命名、固定置顶（行首钉子图标）、搜索（带摘要）、删除确认。
- 历史目录（文件夹）行支持右键菜单“在资源管理器中打开”（`reveal_path` 打开该组会话的目录）；会话行右键菜单为：加载（恢复/历史箭头图标，载入该会话）、重命名、置顶固定/取消固定、删除会话。
- 打开历史会话为**只读加载**（`thread/read`），不会触发服务端自动执行；用户真正发消息时才 `thread/resume` 再 `turn/start`。
- 继续执行使用**会话记录的 cwd**（实测 `thread/resume` 返回该值），命令在该目录运行；沙箱可写根（`sandboxPolicy.writableRoots`）同样跟随会话 cwd，避免越权或误弹审批。
- 带**活跃目标**的会话在恢复后会自动持续执行目标（codex 目标模式语义）；因此“打开即恢复”会引发连续回合，故改为发消息时才恢复。
- 窗口标题：有会话时显示会话标题（无前缀）；前端头部只显示当前工作目录（仅新会话态可点击选目录，会话/历史态只读）。

### 右侧面板与会话资源
- 右侧面板（`RightPanel.vue`）为底部固定双 Tab：“历史会话”/“会话资源”，默认历史；`HistoryView` 与 `ResourceView` 均为**单根组件**，Tab 用 `v-show` 互斥切换（保留两侧展开/滚动状态），面板宽度可拖拽（264px ～ 半窗，仅本次运行生效）。
- 会话资源以**当前会话工作目录**为根（会话 cwd → 新会话已选目录 → 启动工作目录，空字符串自动跳过，另有 `workspace_dir` 后端兜底），根节点显示文件夹名、默认展开第一层，子目录**懒加载**（首次展开才拉取）；名称以 `.` 开头的目录（.git/.codegraph/.vs 等）与 `node_modules`（任意深度）始终隐藏。
- 行内信息：文件行显示大小 + 修改时间，目录行显示直接子项数 + 修改时间；行 tooltip 显示完整路径；头部搜索框递归匹配文件/目录名（300ms 防抖、忽略点目录、上限 200 条），点击结果回到树中定位并展开祖先目录。
- 右键菜单：根（粘贴、在此打开终端、在资源管理器中打开）；非根目录（复制、粘贴、删除、重命名、添加为会话附件、在此打开终端、在资源管理器中打开）；文件（复制、属性、删除、重命名、添加为会话附件、在资源管理器中打开）。
- 打开逻辑按扩展名分发：文本文件经 `session_fs_probe_text` 探测后在主窗口左侧标签页以文本编辑器打开；`.pdf` 与图像文件（png/jpg/jpeg/gif/webp/bmp/svg/ico/avif）直接打开只读预览标签；其余非文本提示无法打开。三处入口（右键「打开」/ 文件行单击 / 搜索结果单击）行为一致。
- 复制粘贴：内部剪贴板优先，为空时回退读取系统剪贴板文件（`clipboard_file_paths`），根/目录上粘贴（文件或文件夹，递归复制，禁止粘贴到自身或子目录）；“属性”仅文件提供（名称/类型/完整路径/大小/修改/创建时间）；“添加为会话附件”经 ComposerBar 全局入口 `__CODEX_UI_ADD_ATTACHMENT__` 追加到附件区（图片 `localImage`、其余 `mention`）。
- 自动刷新：后端 `notify` 递归监听根目录（忽略点目录内事件，300ms 防抖）emit `session-fs/changed`；监听跟随“会话资源”Tab 激活与根目录切换（切走停止、切回重建并保留展开状态仅刷新数据）；前端收到事件只刷新已展开分支。
- 右键菜单关闭语义：仅当右侧面板自身滚动、点击外部或按 Escape 时关闭；聊天区等外部滚动（会话流式更新引发的吸底滚动）不再误关菜单。
- 后端 `session_fs` 命令全部做**路径包含校验**（Windows 大小写不敏感，防止越权访问）；输出路径统一清洗 `\\?\` / `\\?\UNC\` 前缀为标准 Windows 路径（属性弹窗、toast、资源管理器打开不再出现前缀）。

### 特殊文件预览（PDF / 图像）

- 资源管理器打开 `.pdf` / 图像文件时进入主窗口左侧标签区的只读预览标签：`PreviewEditorTab`（`kind: "preview"`，`previewType` 区分 pdf/image），重复打开去重激活、关闭无脏确认；标签栏显示「预览」徽标，图标与悬停提示与文件标签一致。
- PDF：后端 `session_fs_read_bytes`（路径包含校验、仅文件、50 MiB 上限）以 base64 返回字节，前端解码后交 pdf.js（v6，懒加载，worker 走 `pdf.worker.min.mjs?url`）渲染当前页 canvas；工具栏含上一页/下一页、页码、缩放（0.25–4 倍，默认适应宽度）与“适应宽度”复位；切换/卸载时销毁文档，损坏或超限文件在标签内显示错误。
- 图像：`convertFileSrc` 生成 asset URL 直显（contain 适配、可滚动），加载失败显示错误；复用既有 `assetProtocol`（scope `**`）与 CSP `img-src asset:`，无需新增配置。
- 扩展名识别与 base64 解码集中在 `lib/preview.ts`（`previewTypeForName` / `base64ToBytes`）；打开逻辑统一在 `requestOpen` 分发，非特殊类型行为不变。

### 主窗口左侧标签页（多标签编辑区）

- 左侧为标签页编辑区（`EditorPane`）：第一个固定「会话」主标签（`kind: "chat"`，不可关闭），其后为文件（CodeMirror）、diff、预览、终端等可关闭标签；标签栏仅在存在非会话标签时显示，文件/diff/预览/终端标签 `v-show` 常驻挂载（切换不销毁状态/进程）。
- 所有标签统一右键菜单（`openTabMenu`）：`关闭所有标签`、`关闭左边所有标签`、`关闭右边所有标签`——左边/右边项仅在该侧存在可关闭（非会话）标签时显示；会话标签固定在首位（左边项恒隐藏）且不可关闭（`closeAllOtherTabs` 天然排除会话标签），无需特判。
- 批量关闭逻辑在 `useEditorTabs`（内部 `closeTabsMatching`）：未保存（脏）文件标签跳过并 toast 提示数量、终端标签直接结束进程；对外提供 `closeAllOtherTabs()` / `closeTabsToLeft(id)` / `closeTabsToRight(id)`。

### 终端标签（PowerShell）

- 资源管理器根目录/子目录右键「在此打开终端」在主窗口标签区新建独立终端标签：后端 `codex::terminal` 用 `portable-pty`（Windows ConPTY）启动 `powershell.exe -NoLogo -NoExit`，启动命令将控制台输入/输出编码固定为 UTF-8（`chcp 65001` + `[Console]::Input/OutputEncoding`），中文/Unicode 输出经 ConPTY 读回不乱码；启动命令另覆写 `prompt` 函数（每次回到提示符先输出隐藏标记 OSC 133;D，前端据此判定命令执行完毕）并设置会话级默认参数 `$PSDefaultParameterValues['Invoke-WebRequest:UseBasicParsing']=$true`（消除 2025-12 安全更新 CVE-2025-54100 新增的“脚本执行风险”确认弹窗）。
- 命令：`terminal_spawn(id, cwd)` / `terminal_write(id, data)` / `terminal_resize(id, cols, rows)` / `terminal_kill(id)`（幂等）；reader 线程分块 emit `terminal/output`，EOF 后取退出码 emit `terminal/exit`（{id, exitCode}）并清理会话；会话表 `TerminalState` 由 setup 注入，应用退出时随 drop 清理全部 PTY。
- 前端 `TerminalEditorTab`（`useEditorTabs`）每次调用 `openTerminalTab(cwd)` 生成唯一 id 并激活，同目录可多开，标签标题固定为 PowerShell（无 ToolTip）；标签 `v-show` 常驻挂载，切换标签进程不中断；命令执行中（`busy`）标签显示呼吸圆点；关闭运行中的终端先弹确认（确认后终止进程），批量关闭（关闭所有/左边/右边）跳过运行中的终端并提示数量，空闲/已退出终端直接结束进程。
- 事件同步经 `useTerminalEvents` 单例事件桥：`openTerminalTab` 在 `terminal_spawn` 之前先注册全局 `terminal/output` / `terminal/exit` 监听并建立按 id 缓冲，`TerminalPane` 挂载后 `flush()` 回放启动输出（含 ConPTY 的 `CSI 6 n` 光标查询，xterm 写入后自动应答，提示符正常渲染）再转实时分发；缓冲退出码直接置 `tab.exited`，标签关闭时 `releaseTerminal` 清空缓冲。`TerminalPane.vue` 用 xterm.js（`@xterm/xterm` + `@xterm/addon-fit`）渲染：深色主题、onData 转发输入，并在原始输出流扫描 OSC 133;D 提示符标记（跨块拆分拼接）、检测回车/粘贴换行维护 `busy` 状态（呼吸灯）；`watch(tab.loading)` 在 spawn 完成后补一次 `fit()` + `syncSize()`（消除 resize 早于 spawn 被拒的竞态）；进程退出显示「进程已退出（代码 X）」覆盖层并禁用输入。

### 文本编辑器与 Markdown 预览

- 文本文件在主窗口左侧标签页以 CodeMirror 编辑器打开（行号、历史、查找/替换、软换行、脏标记与保存）；编辑区右键为自定义菜单：撤销、重做、剪切、复制、粘贴、全选、查找/替换、**代码格式化**——剪切/复制按选区显示，右键定位光标到点击处，粘贴经 Clipboard API 读取（WebView2 不支持 `execCommand("paste")`）。
- 代码格式化覆盖编辑器已注册的全部语言，按扩展名三档路由（`src/lib/codeFormat.ts`）：JS/TS/JSON/JSONC/CSS/HTML/YAML/Markdown 动态加载 Prettier（`tabWidth: 4`，可展开单行）；XML/SVG 基于 `@lezer/xml` 语法树自定义美化（属性/注释/DOCTYPE/CDATA/自闭合与文本原样保留，错配标签拒绝格式化）；Python/Go/Rust/C/C++/Java/Kotlin/C#/PHP/SQL/Shell/PowerShell/Ruby/INI 等复用 CodeMirror 内置缩进规则重排（仅修正已有换行的缩进）。格式化结果以单次可撤销事务写入并置脏，语法错误 toast 提示且不改动文档，保留 CRLF/LF 与结尾换行。
- `.md` / `.markdown` 文件头部提供「预览/编辑」切换：预览复用聊天区 `MarkdownText` 渲染当前文档，编辑器视图 `v-show` 保留状态，切回编辑时内容/脏标记/光标不丢；预览态下 Ctrl+S 仍可保存。
- 滚动条：diff 查看器、文本编辑器、会话区与 Markdown 预览区统一 12px 宽，其余面板保持 8px。

### Git 更改
- 第三个 Tab「Git 更改」（`GitView.vue` + `useGitChanges.ts`），**后端内置 gix 0.86**（纯 Rust，不依赖系统 Git，无黑窗体/无 git 可执行文件问题）；以当前会话工作目录（与资源 Tab 同链）为根检测所在仓库。
- 后端 `git.rs` 绝大多数操作进程内完成（`spawn_blocking` + 60s 超时）；**拉取/推送**（网络操作）调用系统 git 子进程（600s 超时）：
  - `git_changes_status`：`gix::discover` 向上发现仓库（非仓库错误码 `not_a_repo`），`head_name` 取分支（游离/未出生显示 `HEAD`）；`Repository::status`（`untracked_files(Files)` + 关闭重命名检测）产出 HEAD→索引 + 索引→工作区两类条目，同路径合并（优先级 deleted > added > modified > untracked；冲突简化为 modified 展示），未跟踪文件来自目录遍历；结果无条件过滤含 `node_modules` 组件的路径（即使已跟踪）。
  - `git_changes_init`：守卫非仓库后调用 `gix::init`（默认分支 `main`，仅初始化、不自动提交、HEAD 未出生），返回最新状态。
  - `git_changes_diff`：统一对比 HEAD（暂存 + 未暂存合并；HEAD 未出生视为空），HEAD 树取 blob、工作区读文件，`gix::diff::blob` 渲染 unified diff（`@@ -a,b +c,d @@`，3 行上下文）；二进制（前 8000 字节含 NUL）返回错误提示；无内容变化返回空串。
  - `git_changes_watch_start/stop`：镜像 `session_fs` 的 notify 单槽监听（300ms 防抖）递归监听仓库根目录（`.git` 变化天然在内；git 目录在仓库根外时追加监听）；回调中除排除 `. 开头目录`（.git 除外）与 `node_modules` 外，用 gix 排除栈应用 `.gitignore` 规则（已跟踪文件经索引回退放行，`.git` 内部事件始终放行），emit `git-changes/changed`；非仓库时停止监听并正常返回。
  - `git_changes_push` / `git_changes_git_available`：gix 0.86 无 push 客户端（gitoxide 未实现），推送改为调用系统 git 子进程（`git push -u <remote> <local>:<remote_branch>`，`LANG=C` + `GIT_TERMINAL_PROMPT=0`，600s 超时）；`find_git` 探测 PATH 与常见安装目录，未安装时返回「未检测到系统 git」；失败按关键词映射（非快进→先拉取、认证失败→检查凭证、无提交→先提交）。
- 前端状态机 `loading | ok | not_repo | error`：非仓库显示「添加到 Git」按钮（确认弹窗说明仅 `git init`）；`ok` 态显示分支名 + 文件数 + 刷新按钮 + 文件行（圆形状态图标，悬停提示状态文字），点击行经 `git_changes_diff` 取 diff 后调用 `openDiffTab` 在主窗口左侧标签页打开 diff（`workspace_root` 传仓库根），无内容变化时提示占位。
- 拉取按钮旁新增「推送」按钮：拉取/推送均经 `git_changes_git_available` 探测本机 git；未安装 git、游离 HEAD 或另一侧忙碌时对应按钮禁用（tooltip 提示原因）；成功 toast 结果并刷新状态，拉取/推送忙碌互斥。
- 自动刷新：Tab 激活即刷新 + 手动刷新按钮 + `git-changes/changed` 事件（文件改动、index/HEAD 变化都会触发）；监听跟随 Tab 激活与根目录切换；前端另有刷新互斥与 1s 事件冷却，初始化成功后重建监听。
- 分支管理：点击头部分支名弹出下拉弹层（本地分支列表、当前高亮勾选、行尾删除、底部新建输入框），关闭规则与右键菜单一致（外部点击/Escape/面板自身滚动关闭，聊天区滚动不关闭）。
  - `git_changes_branches`：`references().local_branches()` 列出本地分支，`head_name()` 取当前分支。
  - `git_changes_branch_create`：校验名称（非法字符/空名/HEAD 未出生报错），`edit_reference` 以 `MustNotExist` 创建 `refs/heads/<name>`（前置显式查重），指向当前 HEAD，不切换。
  - `git_changes_branch_delete`：禁止删除当前分支，`edit_reference` 直接删除（等同 `git -D`，不校验是否合并）。
  - `git_changes_branch_switch`：逐路径冲突检查（仅「本地改动与目标内容不一致」或「未跟踪文件将被覆盖」才拒绝；无冲突时未提交改动随分支携带，语义对齐 `git checkout`）→ `diff_tree_to_tree` 计算旧/新树差异（关闭重命名检测）→ 写/删工作区文件 → 索引以目标树为底重建并保留未触及路径的旧暂存条目 → `edit_reference` 将 HEAD 指向目标分支；写失败按「携带路径快照 → 其余路径旧树 → 旧索引 → 旧 HEAD」回滚；返回最新状态。
  - `git_changes_commit`：仅提交已暂存内容——索引全量条目经树编辑器构建提交树（等价 write-tree），`Repository::commit` 写提交并更新 HEAD（作者/提交者按 git 规则回退全局配置与身份环境变量），提交后重建索引；前端「暂存更改」分区内嵌提交栏（消息输入 + 提交按钮 + Ctrl+Enter）。
  - `git_changes_pull`：调用系统 git（`git pull --no-rebase --ff-only <remote> <branch>`，远端/分支解析同 push，`LANG=C` + `GIT_TERMINAL_PROMPT=0`）：快进更新或「已是最新」；**分叉时拒绝**并提示先经 GitView 分支合并手动合并（绝不留下冲突状态）；本地改动会被覆盖时由 git 拒绝且工作区不变；10 分钟超时。
  - gix features 增加 `tree-editor`、`merge`、`blocking-network-client`、`blocking-http-transport-reqwest-rust-tls`；拉取/推送不在 gix 能力范围内（gix 0.86 无 push 客户端，pull 改调用系统 git）。

### 消息与内容渲染
- 用户消息：文本 + 附件；本地图片附件渲染为真实 `<img>`（Tauri asset 协议，`convertFileSrc`），不再显示路径文本；`@文件`/技能显示为标签。
- 时间与分组：助手最终答复按 `startedAtMs` 显示 HH:mm 时间戳（用户消息不显示），跨天自动插入日期分隔线。
- 交互：图片点击灯箱预览、加载失败占位；用户消息气泡保持简洁（不显示复制/重试/时间），助手最终答复可复制；未知消息类型显示友好提示并可展开原始数据。
- 引用发送格式与 VS Code 扩展对齐（经中间层代理抓包验证）：`@` 文件序列化为 `# Files mentioned by the user:` 文本段（单条 text）；`$` 技能序列化为 `[$name](path)` 文本链接并保留结构化 `UserInput::Skill` 项（fork 会注入 SKILL.md 内容）；图片为 `localImage` 结构化项。详见 [引用与附件](引用与附件.md)。
- 助手消息：`item/agentMessage/delta` 流式渲染 Markdown（表格、代码块带“复制”按钮与语言徽标、highlight.js 语法高亮）；链接按类型打开——http/https 走默认浏览器，本地文件/目录（`file:///`、`/D:/`、`D:/`、`D:\` 及 marked 编码形式、相对路径按工作目录解析）经 `reveal_path` 用资源管理器定位/打开；流式期间展示文本节流（≤80ms 刷新一次），结束时立即刷净。
- 思考过程：流式期间默认展开并实时计时，完成后自动折叠，显示耗时；内容完整展示，不限高。
- 工具卡片：
  - 命令执行卡：头部显示真实命令（优先 `commandActions[0].command`）、工作目录、状态、**实时耗时**（进行中只显示一次“进行中”+ 秒表）、实时输出（可展开/收起，渲染截断为末尾 5000 行并提示）、命令一键复制、失败显示退出码。
  - 工具调用卡（MCP/动态工具）：server/tool、参数 JSON、结果、错误。
  - 文件变更卡：add/delete/update 列表 + 差异（diff）渲染；点击文件路径/名称在**独立 Tauri 窗口**中打开预览（原生可调整大小，工具栏含全屏/关闭），单栏内联完整文本 diff（旧行红在上、新行绿在下、中间“旧 | 新”分隔、双行号列，覆盖文件全部内容），右侧滚动条式变更位置指示条（删除红段/新增绿段）。
  - diff 解析在 Rust 完成（`codex::diff`）：`build_diff_preview` 一次 IPC 完成路径解析 + 读文件 + unified diff 反向重建旧内容 + 内联行生成；二进制/读取失败/格式异常回退完整统一 diff。窗口参数经 Rust 共享状态传递，窗口按 label=`diff-preview` 识别（不依赖 localStorage）。
  - 其他：webSearch（查询词）、计划/待办列表。

### 输入区
- 通栏输入框为 **TipTap（ProseMirror）富文本编辑器**（占满底栏），文本与引用（插件/非图像文件/技能）内联混编：插件与非图像文件显示 `@` 前缀、技能显示 `$` 前缀，图片仍显示在输入框下方缩略图附件区；权限模式、任务模式、模型、发送按钮**悬浮在输入框之上、靠底对齐**（纯 CSS，注意 DOM 绘制顺序与 z-index 层级）。
- `@` 触发菜单：文件搜索（模糊结果 + 「选择文件…/选择文件夹…」固定行在前）与插件联合搜索（VS Code 风格，输入 token 时命中插件排在命中文件前）；插件列表为**会话级缓存**——进入会话（应用启动初始新会话、新建会话、打开历史会话）时预初始化 `plugin/list`，同会话复用、切换会话取各自缓存，不回退 `skills/list`；插件行显示接口返回的图标（`composerIconUrl`/`composerIcon`，缺失时品牌色首字母占位）。`$` 技能选择保留原行为（打开菜单时加载 `skills/list`）；`+` 添加内容按钮已移除。
- 发送序列化：**全部内联链接**（对齐 VS Code）——文本与引用按输入顺序交织：文件 `[名称](相对路径)`、插件 `[@名称](plugin://pluginId)`、技能 `[$名称](路径)`，不再生成 Files 段与 `## My request:` 标记；结构化 `UserInput::Skill` 项保留（SKILL.md 注入不变）；回显按内联链接顺序渲染插件/文件 `@名称`、技能 `$名称`，顺序与输入一致。
- 权限模式：请求批准 / 帮我批准 / 完全访问权限；任务模式：执行 / 计划 / 目标（目标模式下用户发送的首条消息纯文本即目标，无目标 chip/对话框；该消息对应回合完成或被终止时自动清除目标并退回执行模式）。
- **上下键选择输入历史**（仅内存，行为类似 Linux shell：↑ 回退、↓ 前进、到末尾清空；多行时光标在第一行才触发）。

- 模型：下拉选择（`model/list`），推理强度跟随模型动态生成；模型按钮显示“名称(强度)”；输入区左侧上下文窗口百分比椭圆框，悬停显示“上下文已用 xx K，共 yy K”。
- 发送/停止二合一按钮；新建会话前可选项目目录（默认启动工作目录）。

## 关键设计决策与踩坑记录

- **历史 cwd 过滤**：`thread/list` 的 `cwd` 过滤是精确匹配；曾因初始化时序（`refreshServer` 与 `refreshThreads` 并行）导致过滤失效而显示全部会话，已改为先取工作目录再加载；最终按需求改为展示全部会话并标注目录。
- **窗口标题权限**：动态改标题需在 capabilities 中启用 `core:window:allow-set-title`。
- **图片渲染**：启用 asset 协议需在 `tauri.conf.json` 配置 `assetProtocol` 并在 Cargo 依赖开启 `protocol-asset` 特性。
- **沙箱映射**：请求批准必须用 `workspace-write` 沙箱，否则“批准并记住此规则”后写入仍被拒（曾误映射为 read-only）。
- **目标自动续跑**：带活跃目标的会话被 `thread/resume` 恢复后会连续自动跑回合，UI 表现为发送/停止按钮交替；解决方式是打开会话只读、发消息时才恢复。
- **v-show 多根组件失效**：`v-show` 只对单根组件生效，多根（内容 + 弹窗）会导致两个 Tab 内容同时显示、上下堆叠；`HistoryView`/`ResourceView` 均改为单根（弹窗移入根 div）。
- **Windows 规范化路径前缀**：`std::fs::canonicalize` 返回 `\\?\` 前缀路径，直接外显会出现 `\\?\C:\...`；后端统一用 `clean_path` 清洗后再返回前端。
- **会话 cwd 空字符串短路**：codex 对无 cwd 会话返回 `""`，`"" ?? workspace` 会短路导致根目录恒为空；取值链改用 `||` 并 trim，根为空时经 `workspace_dir` 兜底并回写全局。
- **文件监听生命周期**：监听只在“会话资源”Tab 激活时运行，切走即停止，避免对大型工作目录持续占用系统资源。
