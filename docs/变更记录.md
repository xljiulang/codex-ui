## 2026-08-13（修复：拉取误拒已暂存更改）

### Pull 守卫改为路径级冲突判定

- 修复：`git_changes_pull` 此前用 `status_sync` 的全部变更文件（含已暂存项）做非空判断，只要暂存了任何文件就拒绝拉取，提示“请先提交或暂存”与用户实际状态矛盾。
- 新行为（对齐 `git pull`）：仅当拉取会改到的路径与本地已暂存/已跟踪工作区改动重叠时才拒绝，并在错误中列出冲突文件；不重叠的本地改动全部保留——已暂存内容在拉取后仍在暂存区，未暂存修改与未跟踪文件原样保留。
- 实现：`apply_tree_diff` 拆分为变更路径计算、工作区文件同步、重建索引并保留暂存项三步；暂存保留回写旧索引条目（暂存删除保持移除），被拉取触达的路径在写入前即拒绝。
- 新增/更新 4 个 Rust 测试（重叠拒绝 ×2、不重叠放行 ×2），lib 共 87 个用例通过。

## 2026-08-13（Git 提交与拉取）

### 提交与拉取能力

- Git 更改面板新增「提交」与「拉取」：
  - 「暂存更改」分区内嵌提交栏：消息输入（textarea，Ctrl+Enter 提交）+ 提交按钮 + 提示行（无暂存时「先在上方暂存更改」，有暂存时「将提交 N 个文件」）；仅提交已暂存内容，未暂存更改保留在工作区，成功后清空消息并 toast。
  - 头部新增拉取按钮（游离 HEAD 或忙碌时禁用，忙碌显示「拉取中…」）：快进优先、分叉时合并，冲突则中止并列出冲突文件；成功后 toast 展示结果（已是最新 / 已快进 / 已合并）。
- 后端新增 2 个 gix 进程内命令（保持零系统 git 依赖）：
  - `git_changes_commit`：索引全量条目经 `gix::object::tree::Editor` 构建提交树（等价 write-tree），`Repository::commit` 创建提交并更新 HEAD（作者/提交者按 git 规则回退到全局配置与身份环境变量，缺失时中文提示），提交后重建索引为提交树。
  - `git_changes_pull`：按 `branch.<name>.remote/merge` 解析上游（无则 `origin` 兜底），blocking fetch 更新远端跟踪 ref；本地==远端→已是最新，远端为本地后代→快进（diff 同步工作区 + 重建索引 + 更新分支引用），分叉→`merge_commits` 合并，冲突中止且不改动工作区/索引；拉取前要求工作区与暂存区干净；网络超时放宽到 10 分钟。
- gix 依赖新增 features：`tree-editor`、`merge`、`blocking-network-client`、`blocking-http-transport-reqwest-rust-tls`（HTTPS 走内置 reqwest + rustls，SSH 依赖系统 ssh，凭据走 gix 凭据助手）。
- 新增 10 个 Rust 测试（提交 5 + 拉取 5）与 8 个 Vitest 用例。

- 未跟踪文件与文件夹均可“添加跟踪”（等同 git add）：未跟踪文件菜单项文案由“暂存”改为“添加跟踪”；未跟踪目录添加跟踪即递归暂存目录下所有文件。

- 新增 6 个 Rust 测试与 7 个 Vitest 用例。

## 2026-08-13（变更文件右键菜单）

### Git 常用文件操作

- Git 更改面板的变更文件行新增右键菜单，全部为 Git 相关操作：查看变更（复用打开 diff）、暂存、取消暂存、还原、添加到 .gitignore、删除文件；仅单文件操作，不做多选，也不含打开文件/资源管理器/复制路径等文件操作。
- `GitFile` 新增 `staged` 字段：HEAD→索引的暂存区变化标记为 true，仅工作区变化/未跟踪为 false；前端据此显隐“暂存/取消暂存”。
- 后端新增 5 个 gix 进程内命令（保持零系统 git 依赖）：
  - `git_changes_stage`：等价 `git add`，先移除旧条目（含冲突各阶段）再登记新条目；工作区已删除则暂存删除。
  - `git_changes_unstage`：索引条目重置为 HEAD 版本（HEAD 无此文件则移除），等价 `git restore --staged`，工作区不变。
  - `git_changes_restore`：完全丢弃该文件本地更改——取消暂存 + 工作区恢复为 HEAD 内容，HEAD 无此文件则删除工作区文件。
  - `git_changes_delete`：等价 `git rm`，移除工作区文件并在暂存区记录删除，逐级清理空目录。
  - `git_changes_ignore`：在仓库根 `.gitignore` 追加 `/相对路径`（不存在则创建、保证末尾换行），重复条目幂等跳过。
- 所有新命令对路径做防御校验：拒绝绝对路径、`.`/`..`、盘符前缀、`.git` 与 node_modules 组件。
- 还原/删除需全局确认弹窗二次确认；操作成功后用命令返回值直接刷新状态，失败 toast 提示，执行期间防重复点击。
- 新增 9 个 Rust 测试与 11 个 Vitest 用例。

## 2026-08-13（Git 更改全面切回 gix）

### 零系统 git 依赖

- “Git 更改”后端由系统 git CLI 全面改为内置 **gix 0.86**（纯 Rust）：状态/diff/初始化/忽略规则全部进程内完成，不再 spawn 任何 git 进程，彻底消除黑窗体、git 未安装空状态与反复拉起 git 的开销。
- `git_changes_status`：`gix::discover` 发现仓库；`Repository::status` 产出 HEAD→索引与索引→工作区条目并同路径合并（deleted > added > modified > untracked；冲突按 modified 简化展示）；关闭重命名检测（重命名显示为删除 + 新增两条）。
- `git_changes_init`：仅 `gix::init`（默认分支 main），不自动提交、HEAD 未出生。
- `git_changes_diff`：统一对比 HEAD（暂存 + 未暂存合并，HEAD 未出生视为空），gix 渲染 unified diff；二进制文件返回错误提示；无内容变化返回空串。
- 监听回调除排除点目录（.git 除外）外，新增 gix 排除栈应用 `.gitignore` 规则（已跟踪文件经索引回退放行，`.git` 内部事件始终放行）。
- 前端移除 `no_git` / `git_not_found` 空状态；保留刷新互斥、1s 事件冷却与 init 成功后重建监听。
- 环境要求移除 `git` 依赖项；Rust 测试保留系统 git 仅作搭建仓库的测试夹具（无 git 时跳过）。

### 修复正文总结阶段吸底滚动失效（工具/思考完成之后）
