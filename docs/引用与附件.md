# 引用与附件（@ / $ / 图片）

本文说明 codex-ui 里 `@` 文件引用、`$` 技能引用与图片附件如何进入 codex 上下文，以及回显如何渲染。发送格式与 VS Code Codex 扩展对齐，差异点经过本机 codex fork（codex-cli 0.146.0-alpha.9.2）实测验证。

UI 输入区：`@` 菜单整合文件搜索（模糊结果 + 「选择文件…/选择文件夹…」固定行）与插件列表（对话级缓存——进入对话时预初始化、同对话复用、显示接口图标，输入 token 时命中插件排在命中文件前）；`$` 技能选择保留原行为（打开菜单时加载 `skills/list`）；`+` 添加内容按钮已移除。下方协议格式与回显前缀保持不变。

## 发送总览

`buildTurnInput`（`src/lib/mention.ts`）把一轮输入组装为协议 `input` 数组：

```ts
[localImage…, text, skill…]
```

- 图片：结构化 `UserInput::LocalImage` 项（原样路径）。
- 文本：单条 `UserInput::Text`，内容为「文件引用段 + `## My request:` + 技能链接 + 用户输入」。
- 技能：结构化 `UserInput::Skill { name, path }` 项（路径转正斜杠）。

## @ 文件引用

### 发送格式

文件引用序列化进单条 text，与 VS Code Codex 扩展抓包确认的格式一致：

```text
\n# Files mentioned by the user:\n
\n## 名称: 路径\n
\n## My request:\n用户输入\n
```

路径统一转正斜杠（`toProtocolPath`）。原因：本机 fork 的协议侧 mention 对 Windows 反斜杠路径解析不到文件，只有正斜杠绝对路径能被读入上下文；模型读文件时两种写法都兼容。

### 上下文进入方式

fork 不会把文本段里的文件路径自动解析并注入内容——文件内容由模型通过工具（如 `Get-Content`）主动读取，这正是 VS Code 扩展的既有行为（抓包确认 VS Code 也只发路径文本）。

## $ 技能引用

### 发送格式

技能走双通道：

1. **文本链接**：`[$name](path)` 拼在 `## My request:` 之后、用户输入之前（VS Code 扩展同款序列化，模型可直接看到链接）。
2. **结构化项**：`UserInput::Skill { name, path }`（路径转正斜杠）。

### 上下文进入方式

实测本机 fork 对结构化 `UserInput::Skill` 会把 `SKILL.md` 内容直接注入模型上下文（不执行工具也能答出技能原文）；对文本 `[$name](path)` 则不会注入，模型需自己读取。因此保留结构化项是为了保证技能内容可靠进入上下文，文本链接则与 VS Code 格式保持一致。

## 图片附件

- 图片作为结构化 `UserInput::LocalImage` 项随 `input` 发送（协议顺序在 text 之前）。
- 前端用 Tauri asset 协议（`convertFileSrc`）在输入区缩略图与消息内渲染真实图片。
- `buildTurnInput` 必须保留 `localImage` 附件——历史重构曾遗漏该类型导致图片未发送。

## 回显渲染

`src/components/MessageItem.vue` 对用户消息逐项渲染：

- 文件引用段 → `@名称` 标签（悬停显示完整路径）。
- 技能链接 → `$名称` 标签（当同一条消息内已有独立结构化 skill 项时不重复渲染）。
- 结构化 skill 项 → `$名称` 标签。
- 纯文本只显示用户实际输入（`stripMentionContext` 去掉文件段、`## My request:` 标记与技能链接）。

输入区附件标签（`src/components/ComposerBar.vue`）：文件显示 `@名称`，技能显示 `$名称`，图片显示缩略图。

## 实现位置

- `src/lib/mention.ts`：`fileMentionSection` / `skillMentionLinks` / `assemblePromptText` / `buildTurnInput` / `parseFileMentionSection` / `parseSkillMentionLinks` / `stripSkillLinks` / `stripMentionContext` / `toProtocolPath`。
- `src/composables/useCodex.ts`：`continueTurn` / `steerTurn` 通过 `buildTurnInput` 组装输入。
- `src/components/MessageItem.vue`：引用标签渲染与去重。
- `src/components/ComposerBar.vue`：附件标签。
- 单元测试：`src/lib/__tests__/mention.spec.ts`。

## 抓包依据

用中间层代理 `codex-proxy`（`D:\codex\codex-proxy`，Rust 转发 + 记录程序）把 VS Code 扩展的 `chatgpt.cliExecutable` 指向代理，抓取扩展与 `codex.exe app-server` 之间的双向 JSON-RPC：

- VS Code 真实发送：单条 text（`# Files mentioned by the user:` 段 + `## My request:` + `[$name](path)` 技能链接），并额外携带 `attachments` 参数。
- 实测 fork 不处理 `attachments` 参数（不注入文件内容），文件仍靠模型读工具。
- 结构化 `UserInput::Skill` 是 fork 上技能内容进入上下文的有效通道。
