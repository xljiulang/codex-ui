# codex-ui 会话级协议盘点

> 基于 `codex app-server generate-ts --experimental` 生成的协议绑定（验证基线 codex-cli 0.146.0-alpha.9.2，2026-08-15 生成）。
> 客户端 → 服务端共约 100 个方法，codex-ui 目前实际调用约 25 个。

## 已实现的会话级协议

`initialize`、`thread/start`、`thread/resume`、`thread/read`、`thread/list`、`thread/search`、`thread/turns/list`、`thread/delete`、`thread/name/set`、`thread/goal/{set,get,clear}`、`thread/metadata/update`、`threadSection/move`（置顶）、`thread/unsubscribe`（标题后台线程）、`turn/start`、`turn/steer`、`turn/interrupt`、`thread/compact/start`、`model/list`、`skills/list`、`plugin/list`、`fuzzyFileSearch`、`thread/settings/update`（模型/推理强度应用后即时同步）、`thread/memoryMode/set`、`memory/reset`（设置页记忆管理）。

服务端反向请求（审批 / 提问 / MCP 表单）走通用 `interaction:request`，目前全部可以接收并内嵌在消息流中响应。

- **消息渲染补齐（2026-08-17）**：新增监听 `turn/plan/updated`（Updated Plan 任务清单，`plan: [{step,status}]`）、`item/reasoning/summaryTextDelta` / `summaryPartAdded`（推理摘要增量）、`item/mcpToolCall/progress`（MCP 进度）；新增 `imageGeneration` / `subAgentActivity` 条目渲染。

> 目标说明：`codex.exe` 没有“目标模式”——`thread/goal/{set,get,clear}` 是把目标挂载/清除到**线程**上，设置后由服务端 auto-continuation 循环围绕目标自动续跑回合，直到完成/预算耗尽/暂停/清除。codex-ui 已按此实现：目标由输入栏 flag 勾选（会话空闲可勾选，回合运行中禁用），勾选后无目标值，发送的首条消息纯文本即目标并自动挂载，消息同时正常发送；打开历史会话时 `thread/goal/get` 回填并渲染（终态不自动清除），监听 `thread/goal/updated`/`thread/goal/cleared` 同步状态，收到终态（`complete`/`budgetLimited`/`usageLimited`/`blocked`/`paused`）自动清目标复位 flag；停止时先清目标再中断。目标状态值与协议 `ThreadGoalStatus` 对齐：`active`/`paused`/`blocked`/`usageLimited`/`budgetLimited`/`complete`——完成绿，预算耗尽/用量受限/阻塞/暂停黄，tooltip 显示对应文案。

## 会话级协议：有但未实现

| 协议 | 用途 | 说明 |
|---|---|---|
| `thread/fork` | 从现有会话分叉出新会话 | 现在只能新建/继续，不能"基于历史分叉" |
| `thread/archive` / `thread/unarchive` | 归档/恢复会话 | 现在只有删除，没有归档 |
| `thread/rollback` | 回滚到更早回合 | 聊天区没有"回滚到此处"能力 |
| `thread/inject_items` | 向会话注入条目 | 可用于注入参考内容/系统消息 |
| `thread/items/list` | 条目级列表 | 现在用 `thread/turns/list` 的 full view 替代 |
| `thread/loaded/list` | 已加载（进行中）会话列表 | 用于"运行中会话"总览 |
| `thread/searchOccurrences` | 会话内全文检索 | 历史搜索只搜标题+摘要 |
| `thread/backgroundTerminals/*` + `thread/shellCommand` | 会话级后台终端 | 与自研 ConPTY 终端并存的可选通道 |
| `thread/realtime/*`（6 个） | 语音/实时会话 | 完整语音协议，未接 |
| `thread/increment_elicitation` / `decrement_elicitation` | 服务端待处理交互计数 | 现在靠前端自己数 interactions |
| `thread/approveGuardianDeniedAction` | 监护人拒绝后的申诉批准 | 桌面端进阶能力 |

## 已用自研方案替代、一般无需再接

`fs/*`（自研会话资源文件树）、`command/exec + process/*`（自研 ConPTY 终端）、`gitDiffToRemote`（自研 gix 差异）、`fuzzyFileSearch/session*`（一次性 `fuzzyFileSearch` 调用替代）。

## 用户提示词（custom instructions）支持情况

- **协议层**：`thread/start` / `thread/resume` 参数支持 `baseInstructions`（用户指令）和 `developerInstructions`（开发者指令）；`turn/start` 的 `collaborationMode.settings.developer_instructions` 每轮可覆盖开发者指令。`ThreadStartResponse.instructionSources` 返回当前会话实际加载的指令源文件。
- **配置文件层**：`~/.codex/config.toml` 支持 `instructions` 和 `developer_instructions` 字段；`~/.codex/AGENTS.md`、`~/.codex/rules/*.rules`、项目 `AGENTS.md` 会被 codex 自动加载为指令。
- **codex-ui 现状**：`newChat` 只传 cwd/权限/模型，`continueTurn` 每轮显式传 `developer_instructions: null`——协议支持但 UI 未接。
