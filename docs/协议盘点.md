# codex-ui 会话级协议盘点

> 基于 `codex app-server generate-ts --experimental` 生成的协议绑定（验证基线 codex-cli 0.149.0，2026-08-23 生成）。
> 2026-09-25 用 **codex-cli 0.156.1** 复核：`ServerRequest` 与 0.154.0 字节一致；`thread/rollback` 已从协议移除（本项目未调用）；`memory/status` 纳入已实现（见下）。差异详见 [app-server.md](app-server.md) §1.2/§1.3。
> 客户端 → 服务端共约 100 个方法，codex-ui 目前实际调用约 25 个。

## 已实现的会话级协议

`initialize`、`thread/start`（含 `dynamicTools`：codexui 动态工具注入）、`thread/resume`（0.156.0 起响应含 `collaborationMode`，用于回填协作模式）、`thread/fork`、`thread/read`、`thread/list`、`thread/search`、`thread/turns/list`、`thread/delete`、`thread/name/set`、`thread/goal/{set,get,clear}`、`thread/metadata/update`（项目/Git 元数据）、`threadSection/list` + `thread/section/move`（置顶，0.149.x 固定协议）、`thread/unsubscribe`（标题后台线程）、`turn/start`、`turn/steer`、`turn/interrupt`、`thread/compact/start`、`model/list`、`skills/list`、`plugin/list`、`fuzzyFileSearch`、`thread/settings/update`（模型/推理强度应用后即时同步）、`thread/memoryMode/set`、`memory/status`（记忆 v2 就绪度，0.156.0 新增；老版本降级隐藏）、`memory/reset`（设置页记忆管理）。

> **设置页插件管理（2026-08-18）**：设置由模态对话框改为统一标签列表中的设置 Tab（`TabKind.Settings`，恒排最后、可关闭，保存后留在页面）；新增内嵌"插件管理"面板，已实现 `plugin/install`、`plugin/uninstall`、`marketplace/add`、`marketplace/remove`，通过 `plugin/list`（`marketplaceKinds: ["local","vertical"]`，覆盖本地市场 + OpenAI 官方垂直目录）浏览，安装/卸载后自动失效并重载会话级 `plugin/list` 与 `skills/list` 缓存。

服务端反向请求（审批 / 提问 / MCP 表单）走通用 `interaction:request`，目前全部可以接收并内嵌在消息流中响应；其中 `item/tool/call`（codexui 动态工具）由 codex-ui 直接应答：`codexui_get_usage` 返回会话用量、`codexui_compact_context` 触发 `thread/compact/start`、`codexui_add_scheduled_task` 创建定时任务（这三条在前端处理），`codexui_send_file_to_wechat` 由后端 Rust 直接应答并执行文件发送（不经前端，见「微信接入」）。实验性，仅新建会话注入。

> **动态工具与 resume 的关系（2026-09-24 复核 0.154.0）**：`dynamicTools` 仍只存在于 `ThreadStartParams`（`ThreadResumeParams` / `ThreadForkParams` / `TurnStartParams` / `ThreadSettingsUpdateParams` 均无该字段），但注册结果会写进线程的 `session_meta.dynamic_tools` **并随线程持久化**——resume 后的回合仍能调用这些工具（微信桥走的正是 resume + turn/start）。

- **消息渲染补齐（2026-08-17）**：新增监听 `turn/plan/updated`（Updated Plan 任务清单，`plan: [{step,status}]`）、`item/reasoning/summaryTextDelta` / `summaryPartAdded`（推理摘要增量）、`item/mcpToolCall/progress`（MCP 进度）；新增 `imageGeneration` / `subAgentActivity` 条目渲染。

> 目标说明：`codex.exe` 没有“目标模式”——`thread/goal/{set,get,clear}` 是把目标挂载/清除到**线程**上，设置后由服务端 auto-continuation 循环围绕目标自动续跑回合，直到完成/预算耗尽/暂停/清除。codex-ui 已按此实现：目标由输入栏 flag 勾选（会话空闲可勾选，回合运行中禁用），勾选后无目标值，发送的首条消息纯文本即目标并自动挂载，消息同时正常发送；打开历史会话时 `thread/goal/get` 回填并渲染（终态不自动清除），监听 `thread/goal/updated`/`thread/goal/cleared` 同步状态，收到终态（`complete`/`budgetLimited`/`usageLimited`/`blocked`/`paused`）自动清目标复位 flag；停止时先清目标再中断。目标状态值与协议 `ThreadGoalStatus` 对齐：`active`/`paused`/`blocked`/`usageLimited`/`budgetLimited`/`complete`——完成绿，预算耗尽/用量受限/阻塞/暂停黄，tooltip 显示对应文案。

## 用户提示词（custom instructions）支持情况

- **协议层**：`thread/start` / `thread/resume` 参数支持 `baseInstructions`（用户指令）和 `developerInstructions`（开发者指令）；`turn/start` 的 `collaborationMode.settings.developer_instructions` 每轮可覆盖开发者指令。`ThreadStartResponse.instructionSources` 返回当前会话实际加载的指令源文件。
- **配置文件层**：`~/.codex/config.toml` 支持 `instructions` 和 `developer_instructions` 字段；`~/.codex/AGENTS.md`、`~/.codex/rules/*.rules`、项目 `AGENTS.md` 会被 codex 自动加载为指令。
- **codex-ui 现状**：`newChat` 只传 cwd/权限/模型，`continueTurn` 每轮显式传 `developer_instructions: null`——协议支持但 UI 未接。
